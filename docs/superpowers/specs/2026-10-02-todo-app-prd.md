## Part 1. PRD

### 1. 개요

하루 10–20개의 할 일을 업무·개인·공부로 나눠 관리하는 개인용 웹 앱이다. 설치나 서버 없이 `index.html`을 브라우저로 열면 바로 실행되고, 데이터는 브라우저 localStorage에 저장되어 새로고침이나 브라우저 재시작 후에도 유지된다.

**목표**

- 할 일을 입력창 하나와 Enter 한 번으로 추가하고, 클릭 한 번으로 완료 처리한다.
- 전체 진행률과 카테고리별 진행률을 한눈에 확인한다.
- 프레임워크·빌드 도구 없이 HTML, CSS, 순수 JavaScript로 구현한다.

**비목표**

- 날짜별 목록, 반복 일정, 알림
- 기기 간 동기화, 로그인, 다중 사용자

### 2. 사용자와 사용 시나리오

사용자는 앱을 만드는 본인 1명이며, 주로 데스크톱 브라우저에서 쓰고 가끔 휴대폰 브라우저로 확인한다.

1. **아침 계획**: 앱을 열고 오늘 할 일 10–20개를 카테고리와 함께 입력한다.
2. **낮 동안 실행**: 끝낸 일을 체크하고, 바뀐 일은 수정하고, 필요 없어진 일은 삭제한다.
3. **중간 점검**: 진행률을 보고 밀린 카테고리를 확인한 뒤, 필터로 그 카테고리만 본다.
4. **다음 날**: 브라우저를 다시 열면 목록이 그대로 있고, 완료된 항목을 한 번에 지운다.

목록은 날짜 구분 없는 **단일 목록**이다. 하루가 지나도 자동으로 정리되지 않으며, 완료 항목은 사용자가 직접 지운다.

### 3. 기능 요구사항

모든 기능은 MVP 범위(P0)다.

| ID | 기능 | 동작 | 수용 기준 |
| --- | --- | --- | --- |
| F1 | 추가 | 제목 입력 + 카테고리 선택 후 Enter 또는 "추가" 버튼 | 앞뒤 공백 제거 후 빈 제목이면 추가되지 않는다. 최대 100자. 추가 후 입력창이 비고 포커스가 유지된다. 선택한 카테고리는 다음 입력에도 그대로 남는다(새로고침 시 "업무"로 초기화). |
| F2 | 수정 | 제목 더블클릭 또는 ✎ 버튼으로 인라인 편집. 편집 중 카테고리 드롭다운으로 카테고리도 변경 | Enter 또는 포커스 이탈 시 저장, Esc 시 취소. 빈 제목으로 저장하면 원래 값으로 되돌린다. |
| F3 | 삭제 | 🗑 버튼 → `confirm()` 확인 | 확인 시에만 삭제되고, 취소하면 아무 변화가 없다. |
| F4 | 완료 체크 | 체크박스로 완료/미완료 전환 | 완료 항목은 취소선·흐린 색으로 표시되고 목록 아래쪽으로 이동한다. |
| F5 | 카테고리 필터 | 탭: 전체 / 업무 / 개인 / 공부 | 선택한 카테고리 항목만 보인다. 선택한 필터는 새로고침 후에도 유지된다. |
| F6 | 진행률 | 전체 막대 + "완료 / 전체 (퍼센트)", 카테고리별 미니 막대 3개 | 추가·수정·삭제·체크 직후 갱신된다. 필터와 무관하게 항상 전체 기준이다. 할 일이 0개면 0%와 "할 일을 추가해 보세요"를 표시한다. |
| F7 | 완료 항목 지우기 | 하단 버튼 → `confirm()` 확인 | 완료 항목만 삭제된다. 완료 항목이 없으면 버튼이 비활성화된다. |
| F8 | 데이터 유지 | 모든 변경을 즉시 localStorage에 저장 | 새로고침·브라우저 재시작 후 목록, 완료 상태, 필터가 그대로다. |

**카테고리**는 업무(`work`), 개인(`personal`), 공부(`study`) 3개로 고정한다. 사용자가 추가·이름 변경·삭제할 수 없다.

**할 일 속성**은 제목, 카테고리, 완료 여부만 다룬다. 우선순위·마감일·메모는 없다.

### 4. 화면 요구사항

최대 너비 640px, 가운데 정렬의 단일 페이지. 위에서 아래로:

1. **헤더**: 앱 이름
2. **진행률**: 전체 막대와 "12 / 18 완료 (67%)", 그 아래 업무·개인·공부 미니 막대
3. **입력 영역**: 제목 입력창, 카테고리 선택, "추가" 버튼
4. **필터 탭**: 전체 / 업무 / 개인 / 공부
5. **목록**: 항목 한 줄 = 체크박스 · 카테고리 배지 · 제목 · ✎ · 🗑
6. **하단**: "완료 항목 지우기" 버튼

- **정렬**: 미완료가 위, 완료가 아래. 각 그룹 안에서는 생성 순서(오래된 것이 위).
- **빈 상태**: 할 일이 하나도 없으면 "할 일이 없습니다", 필터 결과만 비면 "이 카테고리에 할 일이 없습니다".
- **카테고리 색상**: 업무 파랑(`#3B82F6`), 개인 초록(`#10B981`), 공부 주황(`#F59E0B`). 배지와 미니 막대에 같은 색을 쓴다.
- **반응형**: 폭 480px 이하에서 입력 영역을 두 줄(제목 / 카테고리+버튼)로 나눈다. ✎·🗑 버튼은 hover 없이 항상 보여 터치로 누를 수 있다.

### 5. 비기능 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 실행 | `index.html` 더블클릭(`file://`)으로 서버 없이 실행된다. |
| 기술 | HTML, CSS, 순수 JavaScript(ES2015+). 외부 라이브러리·프레임워크·빌드 도구 없음. ES 모듈(`type="module"`)은 `file://`에서 막히므로 쓰지 않는다. |
| 브라우저 | 최신 Chrome, Edge, Safari, Firefox |
| 성능 | 할 일 100개에서도 조작 후 화면 갱신이 체감 지연 없이(100ms 이내) 이루어진다. |
| 보안 | 사용자 입력은 `textContent`로만 표시한다(`innerHTML` 금지). |
| 접근성 | 체크박스·버튼에 레이블(`aria-label`)을 단다. 키보드만으로 추가·체크·삭제할 수 있다. |

### 6. 범위 밖과 완료 기준

**범위 밖**: 날짜별 목록, 사용자 정의 카테고리, 우선순위, 마감일, 메모, 드래그 정렬, 기기 간 동기화, 로그인, 알림

**완료 기준**

1. `index.html`을 더블클릭하면 서버 없이 실행된다.
2. 3절의 F1–F8이 수용 기준대로 동작한다.
3. 할 일 20개를 넣고 새로고침해도 목록·완료 상태·필터가 그대로다.
4. `tests.html`의 테스트가 모두 통과한다.
5. 375px 폭(모바일)에서 레이아웃이 깨지지 않는다.

## Part 2. 설계 스펙

### 7. 구현 방식

세 가지 방식을 검토했고 **A**를 선택했다.

| 방식 | 내용 | 판단 |
| --- | --- | --- |
| **A. 파일 3개 + 일반 `<script>`** | `index.html`, `style.css`, `app.js` | **선택**. `file://`로 바로 실행되고 구조가 단순하다. `app.js` 안에서 역할별로 함수를 나눈다. |
| B. ES 모듈 여러 개 | `store.js`, `render.js`, `main.js` | 경계는 깔끔하지만 `file://`에서 모듈 로딩이 막혀 로컬 서버가 필요하다. 요구사항과 충돌. |
| C. 단일 `index.html` | 모든 코드를 한 파일에 | 공유는 쉽지만 한 파일이 커져 유지보수가 어렵다. |

### 8. 파일 구성

```
study02_B/
├── index.html   # 마크업 뼈대 (#app 루트), style.css·app.js 연결
├── style.css    # 레이아웃, 카테고리 색상, 반응형
├── app.js       # 앱 로직 전부
└── tests.html   # 순수 함수 테스트 페이지
```

### 9. app.js 구조

위에서 아래로 한 방향으로만 의존한다. 상태 변경·계산 함수는 순수 함수라 DOM 없이 테스트할 수 있다.

| 영역 | 함수 | 책임 |
| --- | --- | --- |
| 상수 | `CATEGORIES`, `STORAGE_KEY`, `FILTER_KEY` | 카테고리 목록·이름·색상, 저장 키 |
| 저장소 | `loadTodos()`, `saveTodos(todos)`, `loadFilter()`, `saveFilter(filter)` | localStorage 읽기·쓰기만 담당. 실패 시 기본값 반환 |
| 상태 변경 | `addTodo(todos, title, category)`, `updateTodo(todos, id, changes)`, `toggleTodo(todos, id)`, `deleteTodo(todos, id)`, `clearCompleted(todos)` | 배열을 받아 **새 배열을 반환**. 입력 배열을 바꾸지 않는다. 잘못된 입력(빈 제목 등)이면 원래 배열을 그대로 반환 |
| 계산 | `getProgress(todos)`, `getVisibleTodos(todos, filter)` | 진행률 계산, 필터 적용 + 정렬 |
| 화면 | `render(state)` | 상태 전체를 받아 진행률·필터 탭·목록·하단 버튼을 다시 그림 |
| 이벤트 | `init()` | 이벤트 위임으로 입력 처리 → 상태 변경 → 저장 → `render()` |

`app.js` 마지막 줄은 `if (document.getElementById('app')) init();`이다. 테스트 페이지에는 `#app`이 없으므로 화면 코드가 실행되지 않는다.

**함수 계약**

- `addTodo`: `title.trim()`이 비었거나 100자를 넘으면 원래 배열을 반환한다. 100자 제한은 입력창 `maxlength`와 함수 양쪽에서 지킨다.
- `updateTodo(todos, id, { title?, category? })`: 바뀐 제목이 공백뿐이면 제목은 바꾸지 않는다. 없는 `id`면 원래 배열을 반환한다.
- `getProgress(todos)` → `{ overall: {done, total, percent}, byCategory: { work: {...}, personal: {...}, study: {...} } }`. `percent = total === 0 ? 0 : Math.round(done / total * 100)`.
- `getVisibleTodos(todos, filter)`: `filter`가 `"all"`이면 전체, 아니면 해당 카테고리만 남기고, 미완료 → 완료 순, 각 그룹 안에서 `createdAt` 오름차순으로 정렬한다.

### 10. 데이터와 저장

```js
// localStorage["todos.v1"] — 할 일 배열
[
  {
    "id": "1759370000000-k3f9",            // Date.now() + "-" + 랜덤 4자
    "title": "주간 보고서 작성",           // 1–100자
    "category": "work",                    // "work" | "personal" | "study"
    "completed": false,
    "createdAt": "2026-10-02T09:00:00.000Z" // ISO 8601, 정렬 기준
  }
]

// localStorage["todos.filter"] — 현재 필터
"all"  // "all" | "work" | "personal" | "study"
```

- 앱 시작 시 두 키를 읽어 상태를 만들고, 모든 변경 직후 해당 키에 전체 값을 다시 저장한다.
- 키 이름의 `v1`은 데이터 구조가 바뀔 때 마이그레이션하기 위한 버전 표시다.
- 할 일 20개 기준 약 4KB로 localStorage 한도(보통 5MB)보다 훨씬 작다.

### 11. 오류 처리

| 상황 | 처리 |
| --- | --- |
| `todos.v1`이 없거나 JSON 파싱 실패 | 빈 배열로 시작, `console.warn` |
| 배열이 아니거나 항목 필드가 잘못됨(알 수 없는 카테고리, 빈 제목 등) | 잘못된 항목만 건너뛰고 나머지를 불러온다 |
| `todos.filter`가 허용값이 아님 | `"all"`로 시작 |
| localStorage 접근 자체가 예외(사생활 모드, 용량 초과) | 메모리로만 동작, 상단에 "저장되지 않습니다. 새로고침하면 사라집니다" 배너 표시 |

### 12. 테스트

빌드 도구 없이 두 가지로 검증한다.

**자동 테스트 — `tests.html`**

`app.js`를 불러와 순수 함수를 검증하는 페이지다. 브라우저로 열면 각 테스트의 통과/실패와 합계가 표시된다. 작은 `test(name, fn)`·`assertEqual(actual, expected)` 헬퍼를 페이지 안에 직접 둔다.

| 대상 | 확인 내용 |
| --- | --- |
| `addTodo` | 정상 추가, 빈 제목·공백 제목 무시, 100자 초과 무시, 앞뒤 공백 제거, 원본 배열 불변 |
| `updateTodo` | 제목·카테고리 변경, 빈 제목 무시, 없는 id 무시 |
| `toggleTodo` / `deleteTodo` / `clearCompleted` | 대상만 바뀌고 나머지는 그대로 |
| `getProgress` | 0개일 때 0%, 반올림, 카테고리별 집계 |
| `getVisibleTodos` | 필터별 결과, 미완료→완료 정렬, 생성순 정렬 |
| 저장소 | 저장 후 다시 읽기, 깨진 JSON → 빈 배열, 잘못된 항목 건너뜀, 잘못된 필터 → `"all"` |

**수동 확인 체크리스트**

- [ ] F1–F8을 수용 기준대로 하나씩 확인
- [ ] 할 일 20개 입력 후 새로고침 → 그대로 유지
- [ ] 제목에 `<b>굵게</b>` 입력 → 태그가 글자 그대로 보임
- [ ] 브라우저 개발자 도구에서 375px 폭으로 레이아웃 확인
- [ ] 키보드만으로 추가(Enter)·체크(Space)·삭제(Tab → Enter)
